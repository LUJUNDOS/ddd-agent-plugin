> 按 methods/adversarial-selection.md §2 全量对抗流程执行（2026-08-13）。
> 选型问题：ddd-agent-plugin 应"复用现有方案"还是"自建"？

## 1. 候选

- **A 复用**：直接采用现有方案（gsd-build/get-shit-done 64.7k⭐、spec_driven_develop 等）满足需求
- **B 自建**：以 Projects_dev 蓝本为底自建 ddd-agent-plugin（单一源 + 生成器 + 记忆规程）
- **C 混合**：借鉴现有方案 skill 内容 + 自建框架

## 4. 判决书

**选定方案**：B 自建（内容结构参照蓝本已验证纪律 skill，不复制现有方案内容）
**核心理由**：A 三重致命（归档+单宿主+无记忆）出局；B/C 打平，决胜因素为 C 的"借鉴"无源码级收益、引入溯源成本。
**缺陷缓解**：
- 自维护风险 → 单一源+生成器防漂移 + AC-2/3 真机逐宿主验证
- 冷启动风险 → MVP 仅 5 个纪律 skill，全部对齐蓝本（已验证 1 年+），不发明新方法论
- 工作量风险 → MVP 缩至 2 宿主（reasonix+claude），其余 manifest 预留 P1
**淘汰方案**：
- A 复用：已归档 + 单宿主 + 无记忆设计
- C 混合：借鉴无实质收益，边界模糊
