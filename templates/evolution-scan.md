# evolution-scan —— 记忆进化扫描（长期区维护）

> 与 memory-protocol 分工（无重复）：
> - memory-protocol 管"记 + 晋升"——短期沉淀 error/decision/insight，同类 ≥3 次或显批 → 写入长期区。
> - 本 skill 管"长期区维护"——扫描**已晋升的长期区条目**（不是短期记忆，不重复 ≥3 次判断），做退休/合并/冲突/跨项目提炼。

## 触发
- 用户说"进化扫描""看看记住了什么""沉淀经验""扫描记忆"等意图时自动加载。
- 里程碑/阶段完成后（可选周期触发）。

## 职责（验收标准）
1. **扫描**：读宿主记忆**长期区**条目（CLAUDE.md 固定条目等，即已晋升的经验规则），不扫描短期记录。
2. **退休（30 天规则）**：
   - 长期区条目 `created` 或最近 `hits` 更新距今 > 30 天、且期间无新 error/decision 命中 → 标**退休候选**。
   - **日志窗口护栏**：退休候选进入提案主表前，须确认连续日志（error/decision 记录）窗口 **≥1 周**；窗口不足（空跑/稀疏/仅 1 天）→ 候选**仅作参考、不进入提案主表**——避免引用级命中判定在日志稀疏时产噪、误伤活跃核心规则（见「已知限制 / L4 候选」）。
   - 退休候选**必须经用户确认**后才清理/归档（用户 Oracle 不可跳过）。
3. **合并/去重**：多条长期规则指向同一 `root_cause` → 合并为一条（保留最完整字段 + 累计 `hits`），减少长期区膨胀。
4. **冲突检测**：新晋升规则与既有长期规则矛盾（如同一场景相反结论）→ 列出冲突，交用户裁决，不自行覆盖。
5. **跨项目提炼**：不同项目出现同类 error/decision（长期规则中可辨）→ 提炼为更高层通用原则，标注 `applies_to` 范围。
6. **报告**：输出本次扫描的退休候选 / 合并 / 冲突 / 跨项目提炼清单（含理由），逐项可核。

## 判违规
- 扫描结束不产出四类清单（退休/合并/冲突/跨项目提炼）→ 违规。
- 对短期记忆做"≥3 次提炼晋升"→ 违规（那是 memory-protocol 的职责，本 skill 不重复）。
- 退休条目未经用户确认直接删除 → 违规。
- 冲突条目不交用户裁决自行覆盖 → 违规。
- 修改 memory-protocol 的"记 + 晋升"机制 → 违规（本 skill 只做长期区维护）。

## 已知限制 / L4 候选

- **退休判定的引用检测为逐字/关键词级**：本 skill 退休判定依赖"期间无新 error/decision 命中"，命中检测属引用/关键词匹配，与规则实际"是否被遵守/触发"无语义关联；在中文主导、日志稀疏（空跑或仅 1 天）时会稳定产噪，易误伤英文指纹稀疏的活跃长期区条目（中枢实测：synk 43 规则 + 仅 1 天日志 → 3 条假阳性退休候选，命中 G3 验收、并行 worktree、验证器隔离等核心闸门）。
  - **缓解（已纳入「职责 2」护栏）**：里程碑/阶段扫描前确保 ≥1 周连续日志，不足则退休候选仅作参考、不进提案主表。
  - **根治（L4 结构性升级候选，待评估）**：命中判定升级为**行动语义匹配**——规则绑定触发器 ID / 行为事件检测 / embedding 相似度，确认真实遵守/引用而非关键词偶现。进入评估条件 = 缓解护栏仍不足以抑制噪声，或出现误伤核心规则的真实事故。

## 纪律
- 晋升只在 memory-protocol（短期→长期）；本 skill 只维护已晋升的长期区。
- 与 memory-protocol 串联：记/晋升（protocol）→ 维护（scan：退休/合并/冲突/跨项目），两 skill 互不越权。
- 30 天无触发是退休信号；规则冲突交用户；长期区只保留最有效的规则——避免记忆膨胀与自相矛盾。
